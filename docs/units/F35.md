# F35 atomic website-owned mutation with audit

fidelity: guessed

What works:
- `internal/audit` records the coordinator selection (mutation, schema, actor
  fields, transaction boundary, required role) before any dispatch; incomplete
  selections fail closed with `ErrSelectionUnset`.
- An authorized valid mutation and its audit record commit atomically in the
  synthetic `MemoryStore`.
- Unauthorized (wrong/missing actor) and invalid (empty/control-char) input
  return before the store is touched: no write, no audit row.
- An injected audit failure rolls back the mutation and an injected write
  failure rolls back the audit: no partial commit.
- `SQLStore` uses one transaction with prepared, bound statements over an
  injected `*sql.DB`; no SQL is string-built from values, no production store
  is touched.
- A repeated synthetic target is rejected as `ErrReplay` without adding rows.

What is guessed (owner/security/schema gate open):
- The mutation, audit schema, actor fields, required role, redaction and audit
  retention are UNKNOWN; `SyntheticSelection` is a placeholder shape only.
- Replay protection, rate limiting, HTTP/session binding and real persistence
  are not implemented.

- bash scripts/check.sh
