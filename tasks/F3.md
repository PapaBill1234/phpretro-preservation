# F3 profile read brief

Base SHA: `045714382d432c25473d7d4ec76eb8371868c41e`.

## Exact scope

Allowed files:

- `internal/profile/**`
- `internal/profile/*_test.go`
- `docs/evidence/F3-profile-schema.md`

The implementation must be read-only and use synthetic stores in tests. No SQL migration, production connection, authentication change, or write path is allowed.

## Contract

Implement lookup by numeric user ID and normalized username, returning only `id`, `username`, `motto`, `look`, `gender`, and `account_created`. Use an injected store and a typed not-found result. Do not expose password, mail, IP, machine, token, rank, currency, room, or authorization fields.

## Done criteria

- Source-backed mapping agrees with `docs/evidence/F3-profile-schema.md`.
- Bound lookup inputs and deterministic not-found behavior are tested with synthetic data.
- Malformed gender is rejected or represented as an explicit error; it is never guessed.
- `go test ./...`, `go test -race ./...`, and `gofmt` pass.
- No secrets, real user data, migrations, or writes are present in the diff.

## Stop conditions

Stop on unknown schema, guessed field semantics, any real data, any write requirement, a security or authorization decision, secret detection, quota/auth/payment failure, or a second failed test attempt.

## Economics

Provisional cap: 60,000 uncached input tokens, 40,000 cached input tokens, 12,000 output tokens, 90 minutes wall time. Record actual A6API model, reasoning effort, token counts, retries, wall time, Jev calls/cost, and acceptance status. Luna delegation is optional only if bounded extraction repays its second context.
