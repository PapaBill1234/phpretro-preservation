# F5 content read brief

Base SHA: `294dfd193571c7254398b7e0ecb9835019f34194`.

Allowed files: `internal/content/**`, `docs/evidence/F5-content-schema.md`, and `tasks/F5.md` only.

Implement an injected, read-only news store returning at most ten records ordered by descending ID. The record contains `id`, `title`, `text`, `button_text`, `button_type`, `button_link`, and `image`. Accept only `client` and `web`; map them to stable typed values without guessing. Use synthetic stores in tests.

Done criteria: source-backed field mapping; deterministic ten-row cap/order; malformed enum rejection; no writes or out-of-scope fields; `gofmt`, `go test ./...`, and `go test -race ./...` pass; no secrets or real rows in the diff.

Stop on guessed schema, unknown enum, production data or traffic, writes, asset/client handoff, secrets, quota/auth/payment failure, or a second failed attempt.

Provisional cap: 60,000 uncached input, 40,000 cached input, 12,000 output tokens, 90 minutes. Record actual model, reasoning effort, token counts, retries, wall time, Jev calls/cost, and acceptance status. Jev and Luna are not justified for this deterministic one-package unit.
