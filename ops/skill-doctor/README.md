# Skill Doctor integration

Pinned upstream: evilstar2016/skill-doctor, MIT, source fe1f942cf715a47faa67def0fa5f07882f3a84dc / 0.7.0. Build the maintained TypeScript source extension with `python3 ops/skill-doctor/build_extension.py`, then install from clean reviewed main using `python3 ops/skill-doctor/install_paused.py`. The installer checks source and package hashes, requires STOP and zero reservations, and never enables coding.

The dashboard provides `/skill-doctor/` for project configuration and `/agent-doctor/` for OpenHands role briefs. OpenHands has its own detected platform and scan option. Runtime findings merge into Overview, Issues and linked resource details; context views cover current sessions, optimization evidence and provider evidence. Local runtime metadata refreshes every 15 seconds while visible. Filters cover runtime, role, model, status and unit/run ID. Scan records and the skill library retain upstream functionality. SDK audit snapshots are observations, not writable runtime deployment targets; changes to active instructions require a reviewed source change.

Coverage includes SDK builders/reviewers, the dedicated OpenHands Canvas API, native Sol supervisor jobs, real Codex history mounted read-only, manual Doctor scans, all A6API inference keys in the billing window, and receipt-backed Portdan fallback usage. Canvas full conversation viewing remains in its linked Web UI. Authenticated gateways whitelist metadata and protect the private journal endpoint. Native auth files, SDK agent objects, provider configurations and secret registries are never mounted into Doctor or returned by its APIs.

New SDK runs keep a private, credential-redacted timeline of the injected brief, assistant messages, tool commands/results, admitted requests, typed provider errors and final state. Retention is bounded at512 events /4000 characters per event; truncation and failed persistence prevent a complete-history claim. Metadata counters separately preserve request context/system/tool-schema estimates and tool errors/repeats. Old SDK full transcripts were never saved and cannot be recovered: missing coverage stays unknown. The only SDK tool is Execute, marked unused only for a completed observed run with requests and zero executions. No automatic prompt pruning or unmeasured savings claims.

A6API account calls remain separate billing evidence: current UTC day, max2000 records, including other callers. Session counters and provider bills are never added twice. Portdan cash checks remain disabled by user; unknown prices are not fabricated. Interactive Canvas spending is independent of controller reservations.

Deep Scan is manual only. A6API Sol6.1 analysis uses Responses with high reasoning and8192 max output tokens. Small connection checks use no reasoning and512 output tokens. Embeddings remain enabled with the configured embedding model. Null or malformed AI audit output raises a visible scan warning. Automatic local collection uses no inference or MCP launches; its five-minute timer refreshes private role/model snapshots, including running receipts. Current snapshots state their source run and status.

CLI: `~/.local/bin/skill-doctor --help`. The loopback UI runs in a constrained Docker container behind the existing PHPRetro login; only its isolated profile, project checkout and native history/work mounts are visible. Headless directory selection uses the manual path input. Manual library/cleanup actions retain upstream preview/confirmation behavior and affect the audit profile; they do not enable builder tools or bypass controller reviews. Windows desktop sessions are outside Ubuntu's scope.

Disable local collection with `systemctl --user disable --now phpretro-skill-doctor.timer`; disable the full UI with `systemctl --user disable --now phpretro-skill-doctor-ui.service`. These are separate from coding STOP, coding timers and the native supervisor.
