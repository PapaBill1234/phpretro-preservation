## Placement and loading decision

Use **project source** at `.agents/skills/phpretro-<name>/SKILL.md`. Eight files occupy that supported Hermes layout. Do not use the broad/global catalog or create user-local copies through `skill_manage`.

For live deployment, copy only each selected skill from an immutable reviewed repository commit into the owning profile's `skills/phpretro/<name>/` tree. The deployment manifest must record source commit, source and destination paths, SHA-256, profile, backup path, and read-back hash. This gives profile-specific loading even when dispatched worktrees are not individually trusted. Do not enable project trust in the live profiles merely to make a primary-checkout test pass; test that path separately if it is later desired. Do not modify the existing broad catalog. A selected evolved candidate must first replace its committed source through review before staging, so the repository remains canonical.

The installed copies would be: coordinator 3; backend 2; frontend 2; reviewer 1; visual 2. `phpretro-worker-handoff` is the single shared procedure copied to the three worker profiles. No skill belongs in shared/global Hermes because these decisions are specific to this repository and board.

All eight entrypoints should have a concise trigger-oriented description plus explicit **When to use**, **Do not use for**, **Procedure**, **Pitfalls**, and **Verification** sections. Every procedure step ends in an observable completion criterion. Use Hermes tools (`search_files`, `read_file`, `terminal`, native Kanban tools) and repository-relative paths. No machine-specific absolute path, secret, production row, or automatic `jev_gate` hook belongs in a skill. `AGENTS.md` remains the policy; skills link to it and implement the procedures without copying its rules wholesale.

## Full staged program and gates

1. **Freeze inventory and atlas.** Save read-only board counts, card/event IDs, Git refs, profile config, source/test/roadmap inventory. The companion atlas covers all 29 archived cards. Gate: every archived ID is classified, including never-run dependency descendants.
2. **Resolve the roadmap truth.** The coordinator reconciles queue/decisions with F14 review and the unintegrated candidate before using any implementation case as live work. Gate: one recorded accepted integration head and explicit authorized/deferred units.
3. **Freeze dataset and baseline.** Run each case in isolated fixtures with the current profile configuration. Use the same A6API model, reasoning, task, starting state, and budget in later skilled runs. Record success, required tests, scope/authority violations, evidence correctness, retries, tool calls, wall time, main-model input/cached/output tokens, and cost. For Jev comparisons, use the same question and main model with and without Jev; record Jev count and estimated cost and answer correctness.
4. **Review and revise authored source, one skill at a time.** The eight files are under `.agents/skills`. Validate trigger boundaries, Hermes frontmatter, and relevant references; use baseline and holdout results for later revisions. Gate: every proposed capability in the coverage table is accounted for without an oversized hub or conflicting instruction.
5. **Static and behavioral validation.** Check path portability, Hermes tool names, profile role boundaries, link targets, no secrets, no contradiction with `AGENTS.md`, and structural skill validation. Run frozen cases and unseen holdouts; compare actual actions and artifacts, not prose similarity. Gate: zero scope/authority violations and every required test/evidence gate is handled correctly or reported blocked.
6. **Targeted evolution.** Run the self-evolution pipeline only on the eight PHP-Retro sources; retain baseline, candidate, metrics, failure trace, and holdout results per target. Keep unrelated Apple/media/global skills out. Gate: reject any candidate that weakens scope, safety, evidence, review independence, or accepted-unit cost despite a narrow score gain.
7. **Stage and shadow.** Copy selected exact versions into isolated copies of one owning profile at a time; open a fresh Hermes session to verify `skills_list`/`skill_view` and run the same paired cases plus holdouts. Gate: expected profile loads each selected skill; other profiles and the live catalog remain unchanged.
8. **Selective live deployment.** For each reviewed profile/skill pair, back up destination, copy exact committed bytes, verify SHA-256 read-back and fresh-session loading, then record deployment manifest. Rollback is one profile/skill restore from that manifest, followed by read-back and a fresh-session load check. Never bulk replace all profiles.
9. **Monitor and iterate.** Track per accepted unit: archived/blocked card rate by cause, stale dispatch, worktree mismatch, rework, reviewer rejection, test/evidence defects, completion time, input/cached/output tokens, retries, Jev calls/cost, and user-visible regressions. Compare matched cases and at least ten accepted live units before claiming cost improvement. Revise or remove weak skills from observed traces; re-run frozen and holdout cases after each change.

Program completion requires all five profiles' ownership/loading decisions, all recurring capabilities explicitly created/merged/retained/omitted, measured before/after card failures, source-backed roadmap-wide tasks, matched baseline-versus-skilled evidence, selective reversible live deployment, and no conflict with `AGENTS.md`. **This document establishes inventory, atlas, architecture, evaluation design, and eight source skills.** The deployment manifest records any loading, staging, and live installation; matched behavioral improvement and evolution remain separate gates.
