fidelity: guessed

Acceptance sources: `docs/evidence/F39-a-audit-redaction.md` defines the
synthetic five-field allow-list, identifier grammar, credential-label rejection
and pre-store validation. `docs/evidence/F35-audit-transaction.md` records the
source-backed atomicity and authorization requirements and the open
owner/security/schema gate. Neither establishes captured legacy parity.

Independently authored inputs and expected records are in
`tests/audit/testdata/redaction_fixtures.json`; expectations are taken from
those policies, not generated by the implementation. All values are synthetic.

`tests/audit/redaction_test.go` uses exported APIs only:

- `TestRedactionExternalCommittedAllowList`: hostname and credential-like
  mutation values persist intact only in the mutation; the committed audit's
  serialized field set and values equal the five-field fixture exactly.
- `TestRedactionExternalUnsafeIdentifiers`: each of five identifiers is tested
  against empty, 65-character, mixed-case credential-label, control-character,
  space, non-ASCII and slash inputs. RedactRecord rejects them; dispatch never
  calls the injected store; direct MemoryStore entry rejects unsafe records.
  Empty actor/action/role/target inputs may fail earlier at authorization,
  selection preparation or mutation validation, still before any store call.
- `TestRedactionExternalSafeBoundaries`: 1- and 64-character identifiers and
  the allowed ASCII punctuation are preserved unchanged in every field.
- `TestRedactionExternalAuthorizationAndFailures`: wrong role, missing actor,
  injected audit failure and injected mutation failure leave no committed pair.
  Retrying with valid authorization and cleared failures commits exactly once.

The call observer delegates writes to the production MemoryStore: it counts
entry only and does not simulate atomicity. No mock database, network, secrets,
production schema or SQL driver is involved. SQL rollback and affected-row
behavior are not newly established by this unit.
