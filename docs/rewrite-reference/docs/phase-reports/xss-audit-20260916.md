# XSS audit — 2026-09-16

This is an audit inventory only. It intentionally records the full set of
confirmed output-context issues before any remediation changes are made.

## Scope and method

Reviewed every non-reference PHP source file for member-controlled values,
raw-HTML opt-outs (`HoloText(..., true)`), URL/CSS attributes, inline
JavaScript, Prototype `innerHTML`/`Ajax.Updater` sinks, and staff-controlled
site settings. Forum/guestbook/minimail/profile/group/tag output was traced
from request/database to rendered fragment.

`HoloText()` encodes HTML text and double-quoted attributes, but uses
`ENT_COMPAT`, which does not encode apostrophes and is not suitable for
JavaScript, URL, or CSS contexts.

## Reviewed member-content routes

No additional unprivileged stored XSS was confirmed in this pass for these
paths: profile motto, username, guestbook, minimail, forum posts, group name /
description, room names/descriptions, tags, MyHabbo note text, and search
fragments. They reach normal HTML through `HoloText()` or the hardened
`habbletForumText()` BBCode path. Their AJAX fragments are inserted through
legacy Prototype APIs, so retaining HTML encoding at every server-side output
is mandatory.

The MyHabbo note renderer permits raw HTML only when the editor rank is above
5. This is a trusted-staff exception, not member content. It must remain rank
guarded and should be documented rather than silently treated as safe input.

## Deliberately trusted HTML

The following are not safe for untrusted data and must remain limited to fully
trusted site administrators: `site_tracking`, raw banner HTML, raw welcome
text, and staff-authored rich content. A staff account compromise has site-wide
script execution impact by design.

## Fix order

1. XSS-01: public reflected XSS in the failed-login redirect.
2. XSS-02 through XSS-04 and XSS-10: content and feed rendering.
3. XSS-07 through XSS-09: settings in attribute and JavaScript contexts.
4. XSS-05 and XSS-06: make the intentional trusted-HTML boundary explicit and
   limit non-HTML URL fields.

## Remediation in this branch

XSS-01 through XSS-04, XSS-07, XSS-08, and XSS-10 are remediated here. Normal
`HoloText()` output now escapes both quote types; URL/CSS sinks use `HoloUrl()`
to allow only HTTP(S) and simple local paths; JavaScript values use `HoloJson()`.

XSS-05 and XSS-06 remain explicit trusted-administrator exceptions: raw banner
HTML and tracking snippets are designed to execute markup/script supplied by a
site administrator. Their ordinary URL/image fields now use `HoloUrl()` and
external links receive `noopener noreferrer`.

XSS-09 is recorded for the retired Flash/Shockwave client configuration and is
not altered in this branch. It needs a client replacement rather than piecemeal
escaping because the whole object markup is constructed inside an inline
JavaScript string.
